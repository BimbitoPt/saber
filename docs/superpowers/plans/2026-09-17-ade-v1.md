# MSTUDIO ADE — V1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A local web dashboard (Bun + TanStack Start, port 8082) where the user spawns opencode agents on projects, watches live output, runs the project dev server, and sees a browser pane the agent uses to self-verify its work.

**Architecture:** One TanStack Start app. Server routes own three subsystems: (1) `providers/` spawns opencode (`opencode run --format json` streams JSON events over SSE to the UI), (2) a dev-server registry spawns `bun dev` per project and health-checks the port, (3) Playwright drives a headless Chromium, screenshotting to a route the browser pane displays. The agent self-verification loop is enabled by an `AGENTS.md` + skill doc telling agents to use the screenshot/DOM endpoints.

**Tech Stack:** Bun 1.3.x, TanStack Start + React + Tailwind (v4, `@tailwindcss/vite`), TypeScript, vitest, `playwright` (npm), opencode CLI (`opencode run --format json --dir <path>`), port 8082.

## Global Constraints

- Port 8082 only (8080 = Mstudio/Pontea conflict, 8081 = Clipflow).
- Package manager: Bun only. Never npm/pnpm install.
- PowerShell 5.1 host; all scripts must run under PS 5.1.
- Secrets stay out of git (placeholder `SET_ME`).
- Windows paths; spawn via `child_process` with `"shell": false` and resolved exe paths.
- No emojis in code/docs.
- Repo: `%USERPROFILE%\Desktop\mstudio-ade`.

- [ ] **Step 4: Write opencode.ts (minimal implementation)**

```ts
import { spawn } from "node:child_process";
import { CONFIG as DEFAULT_CONFIG } from "../config";
import type { AgentProvider, SpawnOptions } from "./types";

// Pure helper so tests never need opencode installed.
export function buildArgs(opts: SpawnOptions): string[] {
  const args = ["run", opts.task, "--format", "json", "--dir", opts.workdir];
  if (opts.model) args.push("--model", opts.model);
  return args;
}

// exe (file) and args (string[]): provider.model can override; provider.workdir is cwd.
export function opencodeProvider(exe = DEFAULT_CONFIG.opencodeExe): AgentProvider {
  return {
    name: "opencode",
    args: buildArgs,
    spawn(opts) {
      return spawn(exe, buildArgs(opts), { shell: false, cwd: opts.workdir, stdio: ["pipe", "pipe", "pipe"] });
    },
  };
}
```

- [ ] **Step 1: Write sessionStore.ts**

```ts
import type { ChildProcessWithoutNullStreams } from "node:child_process";

export interface SessionRecord {
  id: string;
  project: string;
  task: string;
  status: "running" | "done" | "stopped" | "error";
  proc: ChildProcessWithoutNullStreams | null;
  eventCount: number;
}

const sessions = new Map<string, SessionRecord>();

export function register(s: SessionRecord) { sessions.set(s.id, s); }
export function get(id: string) { return sessions.get(id); }
export function list() { return [...sessions.values()].map(({ proc, ...rest }) => rest); }
export function snapshot(id: string) {
  const s = sessions.get(id);
  return s ? { ...list() && null, project: s.project, task: s.task, status: s.status, eventCount: s.eventCount } : null;
}
```

(Drop `snapshot` if unused; consolidate helpers as implemented. IDs: `crypto.randomUUID()`.)

Pseudo-logic (exact wiring is TanStack-version dependent — check `@tanstack/react-start` docs for server-function streaming at implementation time):

```ts
import { createServerFn } from "@tanstack/react-start";
import { getProvider } from "../providers";
import { register, get, list } from "../sessionStore";

const startSession = createServerFn({ method: "POST" })
  .validator((d: unknown) => d as { project: string; task: string; model?: string })
  .handler(({ data }) => {
    const provider = getProvider();
    const proc = provider.spawn({ workdir: data.project, task: data.task, model: data.model });
    const id = crypto.randomUUID();
    const record = { id, project: data.project, task: data.task, status: "running" as const, proc, eventCount: 0 };
    register(record);
    // events appending: stdout data → record.eventCount++, broadcast to live SSE response list
    return { id };
  });

const stopSession = createServerFn({ method: "POST" })
  .handler(({ data }: { data: { id: string } }) => { get(data.id)?.proc?.kill(); });

const listSessions = createServerFn({ method: "GET" }).handler(() => list());

export { startSession, stopSession, listSessions };
```

Broadcast mechanism: module-level `Map<string, Array<(ev: unknown) => void>>` of SSE subscriber callbacks (subscribe/unsubscribe pattern) inside `src/server/sessionBus.ts`:

```ts
const subs = new Map<string, Set<(ev: unknown) => void>>();
export function subscribe(id: string, cb: (ev: unknown) => void) {
  if (!subs.has(id)) subs.set(id, new Set());
  subs.get(id)!.add(cb);
  return () => subs.get(id)!.delete(cb);
}
export function emit(id: string, ev: unknown) { subs.get(id)?.forEach(cb => cb(ev)); }
```
